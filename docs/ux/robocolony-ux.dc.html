TURN 01 · ROBOCOLONY · UX PASS

The instrument, not the arcade.

Nine screens. The match view is designed to every state — live, robot camera, replay — because that is where the game is understood. The other four surfaces are set at the same fidelity so the vocabulary holds across the product.

SYSTEM · CHROME

Monochrome paper. 1px hard rules, 2px offset shadows, square corners, JetBrains Mono only. Hover inverts. Nothing glows.

SYSTEM · ARENA

Colour lives inside the viewport and nowhere else — terrain, component kinds, the eight colony hues, taken from app.css unchanged. When the map is the only coloured thing on screen, the eye goes there.

First match

Not a tutorial overlay. One screen that tells the truth: the starter kit is unarmed, it will probably die, and that is the lesson.
[robocolony]
STEP 1 OF 3 · WHAT YOU DO

You are not the commander.

You build the robots and write the rules they follow. Then they compete without you — including while you are logged out. Nothing on this screen steers anything.

01
Assemble a blueprint
Parts compete for one budget and add mass that slows the robot down.
02
Write a priority list
Every robot re-decides every tick. The first rule that matches takes the tick.
03
Watch, and find out what you forgot
Two robots walking past each other facing the wrong way is not a bug. It is the game.
YOU DO NOT HAVE TO WRITE ANYTHING YET

A colony that has approved nothing opens with the built-in starter kit. It is unarmed. Against the aggressive AI it usually dies — which is the moment to open the editor.

START WITH THE STARTER KIT → OPEN THE EDITOR FIRST
TWO SENSES, DRAWN DIFFERENTLY

A robot sees 90° and six cells in front of its nose, and nothing else. Radar, if you paid the mass for it, answers in every direction. If it did not perceive a thing, no rule of yours can react to it.
